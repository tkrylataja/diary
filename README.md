# Щоденник аналізів

Особистий застосунок для лабораторних аналізів: пакет аналізів за датою і динаміка показника за роки. Працює повністю в браузері, без сервера й акаунтів. Дані зберігаються в одному зашифрованому файлі `public/data.enc` (AES-GCM 256, ключ із пароля через PBKDF2-SHA256, 600 000 ітерацій).

## ⚠️ Важливо

- **Пароль не відновлюється.** Якщо його втрачено, розшифрувати `data.enc` неможливо.
- **Робіть резервну копію JSON** (розділ «Дані» → «Резервна копія без шифрування») і тримайте її лише на своєму пристрої. Відновити дані з неї можна там само: «Відновити з JSON». JSON читається без пароля: ніколи не додавайте його в репозиторій. `.gitignore` уже ігнорує `backup*.json`, `*.plain.json`, `*.csv` і `.env.local`.
- У репозиторії не буває незашифрованих даних. Для розробки є лише вигадані демо-дані в `demo/`.

## Розробка

```bash
npm install
npm run dev          # http://localhost:5173/diary/ (без data.enc відкриється «Створити нову базу»)
npm run dev:demo     # те саме, але з демо-базою demo/data.enc, пароль demo-demo-demo
npm test             # тести (vitest)
npm run lint         # ESLint
npm run typecheck    # tsc
npm run build        # білд у dist/
```

Демо-дані лежать у `demo/demo-data.json`. Після їх зміни перешифруйте файл:

```bash
npm run demo:encrypt
```

## Оновлення даних на сайті

1. Додайте аналіз у застосунку.
2. «Дані» → «Завантажити data.enc».
3. Замініть `public/data.enc` у репозиторії, зробіть коміт і пуш. GitHub Pages оновиться за 1–2 хвилини.

### `npm run deploy-data`

Скрипт бере найновіший файл `data*.enc` (зокрема «data (1).enc») із папки «Завантаження», перевіряє, що це справді зашифрований файл бази, і копіює його в `public/data.enc`.

Один раз створіть `.env.local` (він не комітиться) зі шляхом до папки:

```bash
cp .env.local.example .env.local
```

і за потреби відредагуйте `DOWNLOADS_DIR`. Без `.env.local` скрипт шукає в `~/Downloads`.

Далі після кожного «Завантажити data.enc»:

```bash
npm run deploy-data
git status                     # має бути змінено лише public/data.enc
git add public/data.enc
git commit -m "Аналізи <дата>"
git push
```

## Імпорт з CSV або Excel

«Дані» → «Імпорт з CSV або Excel». Перший рядок — заголовок із колонками:

```
date, lab, analyte, value, unit, ref_low, ref_high
```

Обов'язкові: `date`, `analyte`, `value`. Дата у форматі `2024-03-04` або `04.03.2024`; десяткові числа з комою або крапкою; значення може бути текстом (`<0.5`). CSV може бути з комою або крапкою з комою як роздільником. Excel — лише `.xlsx`. Перед імпортом застосунок показує перегляд, рядки з помилками й назви, яких немає в списку показників.

## Публікація на GitHub Pages

Сайт збирається й публікується автоматично (`.github/workflows/deploy.yml`) при кожному пуші в `main`. Перед публікацією проганяються перевірка типів, ESLint і тести: якщо щось не проходить, старий сайт лишається як був.

Один раз потрібно ввімкнути Pages у репозиторії: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Адреса сайту: <https://tkrylataja.github.io/diary/> (`base` у `vite.config.ts` збігається з назвою репозиторію; якщо перейменувати репозиторій, змініть і його).

### Перший запуск

1. Поки в репозиторії немає `public/data.enc`, сайт показує «Створити нову базу».
2. Створіть базу з довгим паролем (фраза з 4–5 слів), додайте аналізи.
3. «Дані» → «Завантажити data.enc», покладіть файл у `public/` (або `npm run deploy-data`), закомітьте й запуште.
4. Через 1–2 хвилини відкрийте сайт, оновіть сторінку (Ctrl+Shift+R) і введіть пароль.

Сайт не надсилає жодних запитів за межі свого домену: шрифти й бібліотеки входять у збірку, аналітики немає, а `Content-Security-Policy` забороняє сторонні джерела. Індексацію пошуковиками вимкнено (`robots.txt` і `noindex`).
